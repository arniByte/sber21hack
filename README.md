# Контур

Контур проверяет, улучшают ли публичные события торговые сигналы по акциям Мосбиржи. Он обучает две модели, сравнивает их с ценовым импульсом и показывает, сколько осталось после издержек и какой просадкой сопровождалась стратегия. Проект подготовлен для хакатона Lite-Invest × СБЕР 21.

## Открыть рыночный отчёт

Контур проверен на 6 696 дневных свечах SBER, GAZP, LKOH и TATN. Турнирный профиль потерял 1,86% за полгода и 2,09% за пять лет. Последняя свеча в архиве датирована 7 сентября 2026 года. [Результаты четырёх горизонтов, источники и конкурсные критерии](docs/market-study.md)

Для запуска нужен Python 3.12. Выполните из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/prepare_market.py
python -m kontur run --dataset archive --bars data/market-bars.csv \
  --market-snapshot data/market-snapshot.csv --profile contest --horizons --output results/contest
python -m kontur serve --report results/contest/report.json
```

Откройте `http://127.0.0.1:8080` или файл `results/contest/dashboard.html`. Автономная панель открывается без интернета. Готовую панель можно также скачать из артефакта `kontur-market` последней успешной проверки в GitHub Actions.

| Вкладка | Что показывает |
| --- | --- |
| Динамика | Изменение капитала, просадку и журнал сделок по дням для трёх вариантов сигнала. |
| Горизонты | Самостоятельные прогоны выбранного в пресете агента. Раскройте срок для просмотра графика, издержек, даты остановки и баллов. |
| Рынок | До пяти лидеров роста и снижения среди бумаг с ценами закрытия на обе даты. |
| Счёт | Локальный импорт `execution-audit.json`, фактические результаты и динамику на общих с симуляцией датах. |

`--profile baseline` воспроизводит исходный риск-профиль. `contest` ограничивает размер позиции 15%, бюджет дневного риска 0,3%, останавливает новые входы при просадке от 2%. `payoff` использует те же лимиты и обучается на движении до выхода по правилам позиции. История стоимости реального счёта загружается отдельно.

Для демонстрации новостного конвейера без скачивания архива запустите `python -m kontur demo`. Демо генерирует синтетические цены и новости с заранее заданной зависимостью. [Руководство команды](docs/guide.md)

## Проверка до 10 лет

Два многодневных варианта проверены на 11 736 дневных свечах. Простой тренд дал +2,38% за 10 лет, но только 4 из 10 независимых годовых окон закрылись в плюсе. В панели откройте «10 лет» для сравнения с Ridge, фиксированного размера позиции и двойных издержек. [Подробные результаты](docs/decade-results.md)

```bash
python scripts/prepare_market.py --start 2015-01-01 --output data/decade
python -m kontur run --dataset archive --bars data/decade/market-bars.csv \
  --market-snapshot data/decade/market-snapshot.csv --profile contest --horizons --study \
  --output results/decade
python -m kontur research --report results/decade/decade-study.json --output results/decade/research.json
```

Откройте `results/decade/dashboard.html`. Файлы `decade-study.json` и `study-trades.csv` содержат статистику окон, границы обучения и журнал десятилетних сделок. `research` сохраняет сводку и системные промпты локально. Чтобы получить две независимые рецензии, задайте `OPENROUTER_API_KEY` и `OPENROUTER_MODEL` и повторите команду с `--send`. Ключ хранится в окружении. [Протокол проверки](docs/robustness-protocol.md)

Для воспроизведения более свежего окна установите дату окончания скачивания 22 ноября и оставьте границу проверки 7 сентября.

```bash
python -m kontur download --from 2026-08-17 --to 2026-11-22 --output data/decade/iss.csv
python -m kontur merge-iss --archive data/decade/market-bars.csv --iss data/decade/iss.csv \
  --output data/decade/november.csv
python -m kontur run --dataset moex --bars data/decade/november.csv --market-snapshot data/decade/iss.csv \
  --profile contest --horizons --study --holdout-after 2026-09-07 --output results/november
```


## Исторические данные и проверка

```bash
python -m kontur download --from 2021-01-01 --to 2025-12-31 \
  --symbols SBER GAZP LKOH TATN --output data/moex.csv
python -m kontur run --dataset moex --bars data/moex.csv --events data/events.csv \
  --holdout-days 120 --output results/moex
python -m kontur serve --report results/moex/report.json
```

`download` загружает дневные свечи TQBR из MOEX ISS. Для офлайн-проверки передайте совместимый CSV из разрешённого источника. `--events` можно опустить, чтобы проверить работу на одних ценах. В таком случае первые две модели используют одинаковую рыночную информацию. Для дополнительных инструментов или исторических изменений проверьте лот и передайте `--lot ТИКЕР=КОЛИЧЕСТВО`. Дневные свечи сами по себе не подтверждают точное время исполнения и ликвидность.

| Файл | Обязательные поля | Дополнительные поля |
| --- | --- | --- |
| Свечи | `symbol,date,open,high,low,close,volume` | `open_time,close_time` по МСК |
| События | `event_id,symbol,published_at,available_at,source,title` | `author,text,url` |

CSV в UTF-8 с запятыми. События привязываются к тикеру или всему рынку (`MARKET`, `IMOEX`, `*`). Время событий в ISO 8601 со смещением, например `2025-06-03T18:15:00+03:00`. В `available_at` запишите момент, когда информация действительно могла попасть в стратегию. Если время для дневной свечи не указано, используются условное открытие в 10:00 и консервативная отсечка в конце дня по МСК. Цены ISS не скорректированы на корпоративные действия.

Для пополнения архива используйте `python -m kontur collect --config data/feeds.json`. `feeds.json` — массив объектов `{"url":"https://news.example.org/rss.xml","symbol":"SBER","source":"Название источника"}`. Подставьте адрес публичной RSS- или Atom-ленты, которую можно использовать. Коллектор добавляет уникальные публикации в `data/events.csv` и фиксирует время первого получения. Старые новости, впервые полученные сегодня, не становятся доступны стратегии в прошлых сессиях. Для исторической проверки событий нужен архив с подтверждённым временем доступности.

Бэктест создаёт `report.json`, автономный `dashboard.html`, журнал `simulated-trades.csv`, пресет `preset.json` и прогнозы на дату последней свечи в `latest-signals.json`. В отчёте записаны контрольные суммы входов, параметры модели и границы обучающих окон. Прогнозы на последнюю дату вынесены из метрик исторической проверки.

## Базовые правила стратегии

После закрытия собираем ценовые признаки, доступные к этому моменту события и наблюдаемую реакцию рынка. Ridge прогнозирует доходность следующей сессии от открытия до закрытия. Используем последовательные окна обучения с отсечением незавершённых целей. Для сравнения отдельно обучаем Ridge без событий и запускаем фиксированный ценовой импульс. Состав признаков и ограничения описаны в [протоколе эксперимента](docs/strategy.md).

Стартовый капитал — 35 000 ₽. Сигнал проходит при прогнозе выше 25 б.п. и оценённых затрат. Покупка на следующем открытии с округлением до лота. До двух одновременных позиций, каждая не более 25% капитала. Стоп 1%, цель 1,6%, закрытие к концу сессии. Комиссия и проскальзывание — по 5 б.п. каждое на сторону. Бюджет стоп-риска 0,6% на день. При модельной просадке от 4% новые сделки приостанавливаются. При касании стопа и цели на одной свече первым считается стоп.

## Cassandra и защита результата

`audit` проверяет CSV реальных исполнений и историю переоценки. Локальная схема импорта требует преобразования официальной выгрузки, когда организаторы предоставят её спецификацию. Приложение моделирует сделки и проверяет выгрузки в режиме чтения.

```bash
python -m kontur audit --fills data/executions.csv --equity data/marks.csv \
  --team-id team-01 --output results/execution-audit.json
```

- Исполнения: `team_id,execution_id,situation_id,timestamp,symbol,side,quantity,price,commission,costs`. `side` — `BUY` или `SELL`, количество в бумагах. Частичные исполнения одного сигнала имеют общий `situation_id`.
- Переоценка: `team_id,timestamp,equity,positions_json`. В `positions_json` укажите `{}` или, например, `{"SBER":{"quantity":10,"mark_price":300.15}}` как одно CSV-поле. Нужна начальная пустая отметка на 35 000 ₽ до первой сделки и отметки до последнего исполнения включительно.

Для полного критерия повторяемости нужны 5 реальных ситуаций за 3 торговых дня либо 2 реальные и 30 подтверждённых исторических ситуаций на отложенных данных. Доля лучшей ситуации свыше 60% чистой прибыли отмечается отдельно. Конкурсные баллы подтверждают организаторы. Исторические сделки никогда не попадают в аудит автоматически.

## Профили и разбор через OpenRouter

«Поделиться пресетом» сохраняет JSON с именем профиля, выбранной стратегией, целью обучения, лотами, издержками и лимитами. На поддерживаемых устройствах доступно системное меню отправки. Участник команды может воспроизвести правила на своём наборе свечей.

```bash
python -m kontur run --bars data/market-bars.csv --preset results/contest/preset.json \
  --horizons --output results/replay
```

Локальные ответы на вопросы по отчёту доступны без сети. Для свободных вопросов Мишке задайте на сервере `OPENROUTER_API_KEY` и `OPENROUTER_MODEL` (идентификатор доступной вам модели) и запустите:

```bash
python -m kontur serve --report results/contest/report.json --mishka
```

Кнопка «Спросить Мишку ↗» отправляет в OpenRouter введённый вопрос и сводные метрики выбранной симуляции. Ключ остаётся на сервере. Аудит счёта открывается в браузере локально. Мишка доступен на локальном сервере для отчёта, указанного при запуске. [Документация OpenRouter](https://openrouter.ai/docs/api/reference/overview)
